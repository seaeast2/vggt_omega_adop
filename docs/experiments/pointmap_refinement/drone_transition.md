# 실내 E3d 이후 드론 입력 전환

사용자 요청: 최소 ADOP 방식까지 실내에서 시험하고 개선이 없으면 HKairport·AMtown 같은 드론 샘플로 변경한다. 야외에서 더 좋은 효과가 있을 수 있다는 가설을 시험하며, 그 효과를 사전에 확정하지 않는다.

E3d `tum-freiburg1_desk-E3d-20261112-001`의 사전 개선 판정은 **false**, selected=초기 0회다. 실내 추가 튜닝은 중단한다. [보고서](E3d/tum-freiburg1_desk-E3d-20261112-001/report.md).

## 다음 실행의 구분

| 예약 코드 | 내용 | 현재 상태 |
| --- | --- | --- |
| E0d | 드론 원본 영상·출처 고정, VGGT-Omega 공동 추론, raw 및 E0c 규칙 색 조건 융합 기준선 | HKairport01·AMtown01 완료, [보고서](E0d/README.md) |
| E3e | E0d 초기값에 E3d와 같은 최소 ADOP 방식·고정 색/카메라 정점 이동 | 같은 고정 조건으로 실행, [실행 이력](E3e/README.md) |

HKairport01을 우선 후보로 두고 AMtown01도 같은 방법의 다른 dataset Run ID로 분리한다. 실제 선택 프레임·시간 간격·장면·전처리·입력 해시는 실행 전에 고정한다. 과거 다른 저장소에서 사용한 `[50,70,90,110]`은 참고 이력이며 현재 입력과 동일하다고 가정하지 않는다. 서로 다른 시점의 중첩과 카메라 이동을 확인하되 모델이 예측한 시차를 실제 시차 GT로 부르지 않는다.

두 모델의 과거 PLY와 결과를 현재 Omega 추론으로 대체하거나 섞지 않는다. 각 새 실행에 원본 영상·모델/체크포인트 버전·추론 결과·관측 CSR·실행 코드·카메라별 초기/선택/last·PLY·로그·Manifest를 보존한다. GPU는 샌드박스 밖 호스트에서 실행한다. 완료된 각 실험은 커밋·푸시하고 원격 SHA를 확인한다.

GT가 있으면 출처·보정·유효 영역을 먼저 검증하고 사후 기하 평가를 한다. GT가 없으면 고정 RGB 손실·coverage·원본 해상도 경계/겹침·점 변위를 보고하며, 광도 개선을 실제 3D 정확도 개선으로 판정하지 않는다. 사용 가능하다면 충분한 독립 관측을 가진 구간을 고정해 별도 검증하지만, 동일 공동 추론에 사용한 영상을 독립 held-out이라고 부르지 않는다.

## 입력 제약 해소와 고정 규칙

초기 확인에서 과거 로컬 경로와 드론 입력은 없었다. 이후 사용자가 [UAVScenes HF](https://huggingface.co/datasets/sijieaaa/UAVScenes)를 제공해 입력 제약을 해소했다. Revision `04a224fd14b0b8fdfd2633e68f20471b85c611a5`와 interval5 ZIP을 고정하고 범위 다운로드로 필요한 항목만 추출했다. 메타데이터 이동 proxy를 기준으로 모델 추론 전에 HKairport01·AMtown01 모두 126/130/134를 고정했다. Cache-only 최초 후보 120/124/128과 변경 이유도 기록했다. 과거 실험의 프레임과 동일하다고 가정하지 않는다.

각 장면의 원본 3장을 동시에 새 Omega 추론했다. 대응 LiDAR·pose·저자 보정 정보는 보존했지만 좌표계/영상 왜곡 규약이 독립 검증되지 않아 이번 GT 정확도 평가에는 사용하지 않았다. 데이터셋에 GT가 없다는 뜻이 아니다. E0d는 두 장면 모두 완료했으며 E3e 결과를 같은 범위의 광도/coverage 지표로 보고한다.
