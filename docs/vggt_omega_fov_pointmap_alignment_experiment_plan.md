> 연구 용도: 대학원 졸업논문 실험<br>

## 1. 배경과 연구 질문

기존 [Pointmap Refinement 실험](vggt_omega_pointmap_refinement_experiment_plan.md)은 카메라를 고정하고 개별 정점을 RGB 손실로 이동하는 방법이었다. 이 방법은 사용자 요청에 따라 E3e까지로 종료했으며, 기존 결과와 실패 기록을 보존한다. 미착수 E4~E9를 이번 방법으로 재사용하지 않는다.

이번에는 정점마다 독립적인 이동 변수를 두지 않는다. **한 카메라의 FoV가 바뀌면 그 카메라에서 생성한 모든 점이 같은 카메라 모델에 따라 함께 이동한다.** 입력 3장이 VGGT-Ω에 함께 들어가 생성한, 융합 전 원본 Depth와 카메라 출력을 출발점으로 삼는다. FoV 최적화·효과 판정에서는 프레임별 점군을 유지한다. 그 뒤 별도 C5에서 색·깊이 조건에 맞는 점을 융합해 대표점 수를 줄인다. 점 삭제로 얻은 차이를 FoV 효과로 계산하지 않는다.

- RQ1: 카메라 중심·회전·Depth를 유지한 채 FoV만 보정해 프레임 간 대응점의 3D 차이를 줄일 수 있는가?
- RQ2: 감소한 차이가 수평·수직 성분에만 한정되는가, 다른 카메라 좌표계의 **깊이축 차이와 표면 층 분리**도 줄어드는가?
- RQ3: 단일 공통 보정과 프레임별 보정 중 어느 자유도가 데이터로 식별되며, 보정에 사용하지 않은 대응점에서도 효과가 유지되는가?
- RQ4: 같은 절차가 실내와 드론 샘플에서 어떻게 다르게 작동하는가?
- RQ5: FoV 보정 후 원본 RGB가 비슷하고 깊이가 가까운 점을 융합하면, coverage와 표면을 유지하면서 SLAM 지도에 보관할 대표점 수를 줄일 수 있는가?

프레임 간 내부 정합성 향상과 실제 기하 정확도 향상은 구분한다. GT 검증 없이 “올바른 카메라 보정”이나 “벽 복원 정확도 향상”을 결론내리지 않는다.

## 2. 변수와 고정 조건

[사용 중인 VGGT-Ω 카메라 변환 코드](https://github.com/facebookresearch/vggt-omega/blob/48b23c8ce72c9a8fcf987f0d7f43d8e4870759f6/vggt_omega/utils/pose_enc.py)는 9차원 출력을 translation 3개, quaternion 4개, 수직 FoV, 수평 FoV로 해석한다. 외부행렬은 OpenCV의 world-to-camera 규약이다. 아래 인덱스는 0부터 시작한다.

| 항목 | 이번 계획의 처리 |
| --- | --- |
| `pose_enc[..., :3]`, `[..., 3:7]` | translation과 회전 고정. 외부행렬을 재최적화하지 않음 |
| `pose_enc[..., 7]`, `[..., 8]` | 각각 수직·수평 FoV 보정 대상. 내부 계산은 radian, 보고서는 degree 병기 |
| `depth`, `depth_conf` | 원본 배열 고정. Depth head 재추론·scale/bias·픽셀별 Depth 학습 없음 |
| 원본 RGB | 대응점 추출·C5 색 유사도 gate·시각화에 사용. RGB 손실·색 학습 없음. 원본 관측 색은 불변 |
| 주점 | 처리 영상의 `(W/2, H/2)` 고정 |
| 왜곡·회전·카메라 위치·전역 scale | 보정 변수에서 제외 |
| 점의 출처와 수 | FoV 최적화 중 점 융합·삭제 없음. C5에서만 대표점을 축소하며 모든 원본 프레임·픽셀 ID를 그룹으로 보존 |

카메라 중심 `C_i`, 회전 `R_i`, translation `t_i`는 `x_c = R_i X_w + t_i`, `C_i = -R_i^{-1} t_i`로 정의한다. 중심과 회전을 함께 고정하므로 translation도 고정된다. 저장된 행렬을 임의로 재직교화하지 않는다.

**FoV를 수정한 값만 저장해서는 점군이 갱신되지 않는다.** 매 후보값마다 내부행렬을 재구성하고 원본 Depth 전체를 다시 역투영해야 한다. Depth head를 재실행하는 실험과도 구별한다.

## 3. 역투영 수식과 탐색 변수

영상 크기를 `W×H`, 주점을 `(cx, cy)`라 할 때 카메라 모델은 다음과 같다.

```text
fx = (W/2) / tan(FoV_w/2)
fy = (H/2) / tan(FoV_h/2)

q_i(u,v) = [D_i(u,v) * (u-cx)/fx,
            D_i(u,v) * (v-cy)/fy,
            D_i(u,v)]
P_i(u,v) = C_i + R_i^{-1} q_i(u,v)
```

`D`는 광선 길이가 아닌 **카메라 Z-depth**로 취급하며 C0에서 기존 역투영 구현과 확인한다. FoV를 변경해도 자기 카메라에서의 Z는 `D` 그대로다. 바뀐 `K_i`로 자기 점을 다시 투영하면 같은 `(u,v)`에 돌아와야 한다. 다른 프레임에서 생성한 점과의 공간 관계 및 다른 카메라로의 투영은 달라질 수 있다.

초기 초점거리 `fx0_i, fy0_i`에 대한 역초점거리 배율 `βx_i, βy_i`를 최적화 변수로 둔다.

```text
βx_i = fx0_i / fx_i,       βy_i = fy0_i / fy_i
fx_i = fx0_i / βx_i,       fy_i = fy0_i / βy_i
FoV_w_i = 2 atan(W * βx_i / (2 fx0_i))
FoV_h_i = 2 atan(H * βy_i / (2 fy0_i))
```

초기값은 모두 `β=1`이다. 기본 허용 범위는 **초점거리 초기값의 0.90~1.10배**, 즉 `β ∈ [1/1.10, 1/0.90]`로 사전 고정한다. FoV에 단순히 ±10%를 곱하는 범위와는 다르다. 경계에 도달했다고 자동으로 범위를 넓히지 않는다.

고정된 Depth와 카메라에 대해서는 다음 관계가 성립한다. 이는 이번 계획의 역투영 식에서 직접 유도한 성질이다.

```text
a_x_i(u,v) = R_i^{-1} [D_i(u,v)*(u-cx)/fx0_i, 0, 0]
a_y_i(u,v) = R_i^{-1} [0, D_i(u,v)*(v-cy)/fy0_i, 0]

P_i(β) = P_i(1) + a_x_i*(βx_i-1) + a_y_i*(βy_i-1)
```

따라서 **대응 픽셀을 고정하면 점간 차이는 β의 선형식과 상수항으로 표현**된다. 입력 3장의 주 실험은 6개 변수의 제한된 최소제곱 문제로 구성할 수 있다. 미분 가능 RGB 렌더러를 사용하지 않아도 된다. 최근접 이웃을 매회 바꾸는 ICP 목적함수나 인접점 개수 자체는 이 선형 문제와 동일하지 않다.

## 5. 대응점 생성과 검증 분리

**같은 픽셀 좌표라는 이유로 두 카메라의 점을 대응시키지 않는다.** 또한 보정 결과가 좋아 보이는 최근접점만 남기는 방식으로 평가 대상을 바꾸지 않는다. 같은 장면 지점으로 추정되는 영상 대응점을 먼저 만들고 고정한다.

계획 기본값은 다음과 같다. 실행 전 C1 설정 파일에 확정하고 이후 변경은 별도 회차·amendment로 남긴다.

- 원본 추론 입력과 같은 처리 RGB에서 SIFT 최대 8,192개/프레임, L2 descriptor 매칭, 양방향 ratio 0.75와 상호 일치·일대일 조건을 적용한다. 구현 근거는 [OpenCV 공식 매칭 문서](https://docs.opencv.org/4.13.0/dc/dc3/tutorial_py_matcher.html)다. 실제 실행에서는 설치된 OpenCV 버전과 설정을 기록한다.
- RGB 픽셀만으로 Fundamental matrix RANSAC을 수행한다. 기준은 1.5 pixel, confidence 0.999, seed 0이다. 순수 회전·평면 장면 등에서 F 검증이 퇴화할 수 있으므로 inlier 개수만으로 대응점의 정확성을 보장하지 않는다. 추출 실패 시 보정값을 얻었다고 처리하지 않는다.
- Depth는 대응 좌표에서 고정된 bilinear 규칙으로 읽는다. 네 지지 픽셀 모두 finite·positive이고, 프레임별 고정 confidence 하위 10%를 제외하며, 지지 Depth의 `(max-min)/median ≤ 0.03`인 점을 사용한다. 색·Depth 경계와 외삽을 피하고 마스크를 저장한다. confidence를 보정된 확률로 해석하지 않는다.
- 여러 프레임의 대응을 track으로 묶되 한 track에 같은 카메라의 관측이 둘 이상 들어가면 충돌 track으로 제외한다. 추정된 같은 지점의 track 전체가 한 split에만 들어가도록 한다.
- track의 최소 카메라 ID를 anchor로 삼고, anchor 영상의 16×12 tile ID와 seed의 고정 hash로 약 80% fit / 20% validation을 나눈다. 같은 anchor tile은 같은 split에 들어가게 하며 split 파일을 보정 전에 저장한다. 모든 프레임은 VGGT-Ω의 공동 입력이므로 이를 “미사용 카메라 평가”라고 부르지 않는다.
- 각 카메라 쌍에 유효 대응 최소 100개, fit 50개, validation 20개와 양쪽 영상 각각 4×4 격자 중 6칸 이상의 분포를 요구한다. 부족하면 `NOT_ENOUGH_SUPPORT`로 기록한다. 대응이 적은 쌍을 결과 확인 후 조용히 제외하지 않는다.

FoV 후보에 따라 대응 track·confidence 마스크·Depth 보간값을 다시 선택하지 않는다. 가림·오매칭의 영향은 고정 마스크와 robust loss로 완화한다. 대응점은 영상 기반 추정치이며 대응 GT가 아니다. 반복 무늬, 움직이는 물체, 무텍스처 벽 때문에 실패할 수 있다.

## 6. 목적함수와 계산 방법

고정 대응 `m=(i,u,j,v)`에 대해 같은 월드 좌표계의 점 차이를 계산한다.

```text
r_m(β) = P_i(u;β) - P_j(v;β)
s_i = D_i(u), s_j = D_j(v)              # 원본에서 고정한 양의 깊이
e_m^i = diag(1,1,2) * R_i*r_m / s_i
e_m^j = diag(1,1,2) * R_j*r_m / s_j

L_data = 카메라 쌍별 mean_m { [Huber(||e_m^i||) + Huber(||e_m^j||)] / 2 }
         을 모든 무순서 카메라 쌍에 동일 가중 평균
L_prior = 0.001 * mean_k[(β_k-1)^2]
L = L_data + L_prior
```

Huber는 `hδ(t)=t²/2` if `t≤δ`, 그 밖에는 `δ(t-δ/2)`, `δ=0.01`로 정의한다. 초기 카메라 깊이로 정규화한 무차원 잔차다. `diag(1,1,2)`는 제곱 오차에서 카메라 Z축 가중치를 XY의 4배로 두는 선택이다. 단위가 다른 prior와의 상대 영향도 보고서에 기록한다. fit track만 최적화에 사용한다.

깊이 차이만 최소화하면 XY가 다른 점도 같은 깊이라는 이유로 가까워진 것으로 평가할 수 있다. 따라서 **전체 3D 차이를 제약하면서 양쪽 카메라의 깊이축 차이를 강조**한다. 월드 Z를 카메라 깊이나 중력축으로 간주하지 않는다.

대응 고정 상태의 residual은 β에 대해 affine이다. 제곱 손실은 box 제약을 가진 작은 convex quadratic이며, 위 Huber와 quadratic prior도 convex다. 최대 20회의 IRLS로 풀고, 매 회 내부 bounded least-squares 해의 제약·수렴·KKT 잔차를 확인한다. solver는 C0에서 작은 active-set 방식과 QR/SVD 기반 풀이를 검증하고 버전을 고정한다. explicit inverse normal-equation 풀이는 피한다. 6개 변수의 내부 문제는 각 변수의 하한/자유/상한 상태를 열거하는 방법도 가능하다.

수렴 기준은 `max|Δβ| < 1e-8` 및 목적함수 상대 변화 `<1e-8`을 함께 만족하는 것으로 둔다. 미수렴하면 후보와 이력을 보존하고 `SOLVER_NOT_CONVERGED`로 기록한다. IRLS 근사 해를 검증 없이 정확한 전역해라고 부르지 않는다. 최근접 대응 변경·가시성 변경·실제 카메라의 참값 추정까지 전역 최적임을 뜻하지 않는다.

최적화 중 고정 대응의 잔차뿐 아니라 초기 타 프레임 점 투영의 화면 내부·양의 깊이 coverage를 검사한다. **카메라 쌍별 초기 유효 관측 수를 분모로 고정**하고, 초기 유효했던 점의 coverage 감소를 0.5 percentage point 이내로 제한한다. 후보에서 새로 유효해진 점으로 이 손실을 상쇄하지 않는다. validation track은 이 후보 선택에도 사용하지 않는다.

IRLS 후보와 초기값을 모두 저장하고 coverage를 만족하는 후보 중 fit 목적함수가 가장 작은 것을 선택한다. 이는 전체 coverage 제약 문제의 전역해를 보장하는 절차가 아니다. 최적 fit 후보가 coverage를 위반하면 `COVERAGE_REJECTED`를 함께 기록한다. validation·GT·육안 결과로 checkpoint를 선택하지 않는다.

## 7. 퇴화와 식별 가능성

FoV 변경은 자기 카메라의 X/Y 광선을 변경하며 **원본 Z-depth를 바꾸지 않는다.** 카메라 방향이 거의 같으면 깊이축 잔차는 FoV에 거의 반응하지 않을 수 있다. 모든 카메라가 같은 중심·방향인 설정에서는 XY 축소로 점 차이를 줄이는 등의 퇴화도 가능하다. 회전만 있는 데이터가 언제나 불가능하다고 단정하지 않고, 실제 residual의 민감도로 판단한다.

C1/C2/C3에서 다음을 기록한다.

1. prior를 제외한 고정 데이터 residual 행렬의 SVD, 유효 rank, singular value와 condition number. 상대 rank 허용오차는 `1e-6`이며 condition number `>1e6`은 불안정 표시다.
2. C2는 rank 1, C3는 rank 6이 필요하다. rank 부족·조건 불량이면 `INCONCLUSIVE_FOV_UNOBSERVABLE`로 분류한다. prior 덕분에 수치해가 하나 나왔다는 사실은 식별 가능성의 증거가 아니다.
3. β 각 축의 허용 구간에서 21개 고정 표본으로, 다른 변수를 초기값에 둔 잔차 민감도 곡선을 저장한다. 평평한 곡선과 강한 변수 상관을 표시한다. 이 곡선은 GT나 validation으로 변수를 고르는 수단이 아니다.
4. 최종 β가 허용 경계로부터 `1e-4` 이내이면 `BOUND_LIMITED`로 표시한다. 강한 경계 제약으로 얻은 값은 물리적인 FoV 보정 확인으로 취급하지 않는다.

Depth 자체의 오차, 회전 오차, 카메라 중심 오차를 FoV가 대신 보상할 수 있다. 이 때문에 잔차 감소만으로 원인이 FoV였다고 결론내릴 수 없다. Depth scale/bias나 회전까지 허용하는 변경은 본 계획 밖의 새로운 가설·실험코드로 분리한다.

## 8. 단계별 실행 계획

아래 단계는 **모두 미실행**이다. C0부터 순차적으로 실행하며 구현 검증과 실제 데이터 효과 판정을 구분한다.

| 코드 | 작업 | 주요 산출물 | 다음 단계 조건 |
| --- | --- | --- | --- |
| **C0** | 역투영·FoV 변수·선형식·solver 및 합성 식별 가능성 검증 | 수식/단위 검사, 합성 정답 복구, 퇴화 제어 결과 | 기술 검사 통과. 합성 실패를 실제 실험으로 덮지 않음 |
| **C1** | 실내 raw 기준선, 영상 대응·track split, baseline 잔차·가시성·rank 측정 | 입력 해시, 고정 대응/마스크, 원본 출처별 PLY·투영, 설정 | 대응 지원·민감도 조건 충족 시 C2/C3 진행 |
| **C2** | 모든 카메라·양축에 공통 β 1개 보정 | 초기/최종 FoV·초점거리, 후보 이력, fit/validation 비교 | 공통 보정 효과와 한계 보고. C3 성공을 미리 가정하지 않음 |
| **C3** | 프레임별 수평·수직 FoV 총 6개 보정 | C1/C2/C3 동일 대응 비교, 깊이축/전체 3D·coverage 판정 | rank 부족이면 이 샘플에서는 판정 보류 |
| **C4** | 동결한 절차로 HKairport01·AMtown01 raw에 C1/C2/C3 비교 적용 | 장면별 보고서, 전체 비교표·동일 해상도 그림 | 양 장면의 통과·실패·보류를 모두 보존 |
| **C5** | 실내·두 드론 장면에서 FoV 보정 전/후 원본 RGB·깊이 근접 융합 비교 | 4개 비교군, 대표점 수·coverage·표면 변화·시간/메모리, 원본 관측 매핑 | 융합 검증·점 수 축소·표면 보존을 구분해 판정 |

C2가 효과 없더라도 C3 데이터 rank와 지원 조건을 만족하면 C3를 수행할 수 있다. 실내가 식별 불가능해도 C0 기술 검증이 통과했다면, 실내 상태를 보류로 남기고 사전 정의한 드론 데이터의 C4 지원 검사를 수행할 수 있다. 장면별 threshold를 결과에 맞춰 튜닝하지 않는다.

C5는 각 장면의 FoV 보정값을 확정한 뒤 수행한다. 실내 C3 완료 후 실내 C5를 먼저 실행할 수 있고, C4 완료 후 드론 C5를 수행한다. C5의 점 수나 육안 결과를 보고 C2/C3의 보정값을 다시 선택하지 않는다.

### C0 필수 검증

- `β=1` 역투영을 기존 E0 원본 역투영과 비교한다. float64 직접 계산은 모델 좌표 기준 `atol=1e-7, rtol=1e-6`을 기준으로 하고, 원본 float32 저장 오차는 별도로 기록한다. 회전의 transpose와 실제 inverse 차이도 측정한다. 불일치를 없애려고 원본 카메라를 조용히 수정하지 않는다.
- 모든 후보에서 자기 시점 재투영 오차 `<1e-5 pixel`, 자기 Z가 고정 Depth와 일치하는지 검사한다. 고정 카메라·Depth·RGB 배열의 해시와 점 ID/개수를 검증한다.
- 직접 역투영과 affine 식이 float64에서 `atol=1e-9, rtol=1e-8` 이내로 일치하는지 확인한다.
- 서로 다른 깊이·카메라 방향·위치를 가진 정답 합성 장면에서 초기 초점거리를 ±5%, ±10% 교란한다. 정답 보정값이 범위 안에 있고 데이터가 full rank인 무잡음 조건에서는 초점거리 상대 오차 `≤1e-4` 복구를 요구한다. 경계 정답은 경계 제어로 분리한다.
- 잡음·고정 비율 오매칭을 추가한 조건의 안정성을 측정하되, 무잡음 수식 검사와 구분한다. 작은 내부 quadratic의 해와 KKT 검사를 독립적인 grid/합성 정답으로 확인한다.
- 같은 방향 카메라의 **depth-only 잔차가 FoV에 무감각한 제어**, rank가 부족하도록 구성한 동일 관측 제어, 순수 회전·평면·대응 부족 제어를 포함한다. 식별되지 않는 경우 성공값을 내는 대신 적절한 보류 상태를 내는지 검사한다.

## 9. 평가와 판정

### 9.1 고정 validation 대응 평가

prior를 제외한 전체 3D 상대 오차와 양방향 카메라 Z 상대 오차의 median·mean·p90, Huber data loss를 fit/validation에 각각 보고한다. Z 오차는 각 방향의 `|[R_i r]_z|/D_i`, `|[R_j r]_z|/D_j`이며 해당 방향들을 동일 가중으로 요약한다. 카메라 쌍별 수치도 반드시 제시한다.

정규화 기준과 대응 집합은 초기값에서 고정한다. validation 결과는 최종 판정에만 사용하며 변수 수·손실 가중치·범위·checkpoint 선택에 사용하지 않는다. 결과를 본 뒤 설계를 바꾸면 탐색 결과로 남기고 새 회차에서 검증한다.

계획상 효과 기준은 다음과 같다. 아래 수치는 문헌의 보편 기준이 아닌 **이 실험의 사전 판정 기준**이다.

| 판정 | 조건 |
| --- | --- |
| 기술 검증 통과 | C0 검사·solver 수렴·불변 조건 통과 |
| 프레임 간 3D 정합성 개선 | validation의 양방향 정규화 3D 거리 median이 초기 대비 ≥5% 감소하고 절대 감소 ≥`1e-5`. 쌍별 median의 상대 악화는 1% 이내, coverage 조건 충족 |
| **깊이축 정합성 개선** | 위 3D 조건과 함께 validation의 양방향 Z 상대 오차 median도 ≥5%, 절대 ≥`1e-5` 감소. 쌍별 Z median 악화 1% 이내, 상대 Z 오차 <1%인 비율이 감소하지 않음 |
| 효과 미확인 | 관측 지원·식별 가능성이 충분하지만 해당 개선 기준 미충족. XY만 개선되면 깊이 층 문제 해결로 판정하지 않음 |
| 판정 보류 | 대응 부족, rank 부족, 조건 불량, 경계 제한, 미수렴 등으로 FoV 보정 효과를 신뢰하기 어려움 |

초기 median이 `≤1e-5`이면 개선 여지가 부족한 것으로 별도 표시한다. 상대 악화 비율 계산의 분모는 `max(초기 median, 1e-5)`로 고정한다. C2와 C3의 효과는 각각 C1 초기값과 비교하며 C3가 C2보다 좋은지도 별도로 보고한다.

### 9.2 조밀 점군·벽 층 진단

- 타 출처 점만 사용한 카메라별 상대 Z 차이와 <1%·<3% 일치 비율, 양방향 최근접 3D 거리, 가시성 coverage를 보조 지표로 기록한다. 자기 프레임 점끼리의 완벽한 재현이 지표를 지배하지 않게 한다.
- 동일 대응 픽셀의 차이가 주 평가다. 동적으로 바뀌는 최근접점 개수·출처 혼합 비율은 보조 지표이며 같은 물리 지점이라는 증거가 아니다.
- C1에서 보정 전에 정한 벽 ROI에서 출처별 깊이 분포·층 간 차이·유효점 수를 전후 비교한다. 결과를 보고 ROI를 바꾼 그림은 탐색 시각화라고 표시한다. 적절한 벽 ROI가 없으면 평가 불가로 기록한다.
- C1~C4의 FoV 평가는 모든 원본 점과 프레임 ID를 유지한다. C5의 대표점 축소는 별도 평가·산출물로 두며 점 삭제로 얻은 층 감소를 FoV 효과로 세지 않는다.

### 9.3 실제 정확도와 GT 제한

FoV 보정 단계에서 자기 카메라의 `D`는 고정되어 있으므로 **동일한 자기 Depth의 GT RMSE는 전후 같아야 한다.** 이것을 FoV 보정 효과의 척도로 사용하지 않는다. C5의 융합 대표점은 깊이 평균으로 위치가 바뀌므로 이 불변 조건의 대상이 아니다. 실제 정확도 평가는 검증된 GT 내부행렬·외부행렬로 만든 3D 점/광선이나 교차 시점 기하를 통해 수행해야 한다.

TUM의 기존 GT 연결은 참고하되, 새 카메라 모델 평가에서 resize/crop·GT K·pose·좌표계 적용을 별도로 검증한다. 모델↔GT 정렬/scale을 사용하면 초기값에서 한 번 결정해 전 후보에 고정하고 GT 마스크도 고정한다. 후보마다 재정렬·scale 재적합하거나 GT로 보정값을 선택하지 않는다. GT 평가 준비가 안 되면 내부 정합성 결과까지만 보고한다.

UAVScenes의 LiDAR·pose·calibration은 이 새 평가에 필요한 좌표 변환과 영상 정합을 아직 검증한 것으로 취급하지 않는다. 원본 자료가 있다는 사실만으로 GT 기하 정확도를 보고하지 않는다. 별도 GT 정합 검증을 하지 않은 C4는 내부 정합성 비교다.

### 9.4 C5: 원본 RGB·깊이 근접점 융합

**목적:** FoV로 정렬한 뒤 중복 관측을 대표점으로 줄이는 단계를 준비한다. 향후 SLAM에서 새 프레임을 지도에 반영할 때 쓸 수 있는 규칙과 관측 출처를 남긴다. 이번 C5는 기존 3장 묶음의 오프라인 융합 평가이며 연속 SLAM·추적·loop closure를 실행한 결과는 아니다.

#### 기존 구현과 이번 추가 조건

재사용 기준은 [E0c 코드·설정](../experiments/pointmap_refinement/E0c/README.md) 및 [실행 보고서](experiments/pointmap_refinement/E0c/tum-freiburg1_desk-E0c-20261112-001/report.md)다. E0c는 다음 프레임의 같은 픽셀로 투영된 점에 **그룹 내 원본 RGB 채널별 범위 ≤30**을 적용했다. 당시 설정에는 깊이 차이 gate가 없었고, 같은 색의 서로 먼 표면이 평균될 수 있었다. 이번 C5는 이 이력을 바꾸지 않고 **명시적인 상대 깊이 근접 gate**를 추가한다.

색 판단은 원본 관측의 처리 RGB 8비트 값으로 한다. 프레임 식별용 빨강·초록·파랑을 유사도 판정에 사용하지 않는다. 조명·노출 보정은 하지 않는다. 같은 표면도 색 차이로 거절될 수 있고 다른 표면도 같은 색일 수 있다는 한계를 기록한다.

#### 융합 규칙과 기본값

1. 입력 순서는 기존처럼 `Frame 0 → 1 → 2`로 고정한다. 각 비교군은 자기 FoV/K로 raw Depth를 역투영한 점에서 **새로** 융합한다. 기존 E0c/E0d 융합 결과를 사후 이동·재융합하지 않는다. FoV와 `R/t/C`는 융합 중 고정한다.
2. 누적 지도의 현재 대표점을 새 카메라로 투영한다. 양의 깊이·화면 내부인 점을 기존 E0c의 nearest-pixel 규칙으로 새 관측 픽셀에 연결한다. 반올림·경계 규칙은 기존 코드와 일치시키고 설정에 기록한다. 영상상 같은 픽셀에 들어오지 않는 점은 합치지 않는다.
3. 각 새 픽셀의 원본 관측을 seed로 삼는다. 같은 픽셀 후보는 E0c와 같은 색 차이 우선·현재 점 ID 순서로 검사한다. 후보 수용 후 만들어질 **전체 그룹**에 두 gate를 동시에 적용한다.
   - **색:** 모든 원본 구성 관측에 대해 각 RGB 채널의 `max-min ≤30`. 평균색끼리만 비교하지 않고 원본 RGB min/max를 유지해 연쇄 혼합을 막는다.
   - **깊이:** 새 관측 깊이를 `D_new`라 할 때, 제안 그룹의 원본 구성점과 현재 평균에 사용할 대표점들을 모두 새 카메라의 Z로 변환한다. 모두 finite·positive여야 하며 `(max(Z)-min(Z))/D_new ≤0.03`이어야 한다. 원본 구성점은 해당 비교군의 **융합 전 역투영 좌표**로 계산한다. 즉 대표점만 가깝다는 이유로 원래 멀리 있던 관측을 연쇄적으로 합치지 않는다. 후보를 하나 추가할 때마다 전체 범위를 다시 확인한다.
4. 두 조건을 통과한 이전 대표점의 깊이를 `z_1…z_m`이라 할 때, 새 대표점은 새 카메라 픽셀 광선 위의 `z_new=(D_new+Σz_k)/(1+m)`에 둔다. E0b/E0c와 같이 **현재 대표점당 가중치 1**의 평균이다. 누적 관측 수 가중 평균으로 임의 변경하지 않는다. 통과한 이전 대표점만 제거·치환한다. 거절·비투영 점은 XYZ와 그룹을 그대로 유지하며 다음 프레임에서 다시 후보가 될 수 있다.
5. 그룹의 모든 원본 관측 ID·프레임 ID·픽셀·RGB·confidence를 CSR 매핑으로 보존한다. 각 원본 관측은 최종 그룹 하나에 정확히 한 번 속해야 한다. 대표점 owner는 새 관측으로 정하고 표시 RGB는 owner의 원본 RGB를 사용한다. 원본 색의 산술 혼합은 하지 않는다. 기존 `rgb_fixed_median`을 재사용하면 별도 진단값으로 표시하며 owner RGB와 구분한다.

색 범위 30과 깊이 범위 3%는 C5의 사전 기본값이다. 장면별 결과·GT·validation을 보고 바꾸지 않는다. gate를 통과해도 동일 물리 지점임이 보장되지는 않으며, 법선·표면 모델·카메라 보정 공동 최적화는 이번 융합 범위에 포함하지 않는다. 순차 평균은 프레임 순서와 그룹 이력에 의존하므로 처리 순서와 단계별 매핑을 저장한다.

#### 비교군

| 비교군 | FoV | 융합 | 분리해서 확인할 효과 |
| --- | --- | --- | --- |
| A | C1 초기값 | 없음 | 원본 기준선 |
| B | C1 초기값 | 색+깊이 gate | FoV 보정 없이 융합한 효과 |
| C | C3의 사전 절차로 확정한 값 | 없음 | FoV 보정 자체 효과 |
| D | C와 동일 | 색+깊이 gate | FoV 보정 후 추가 융합 효과 |

A↔B, C↔D는 각각 **동일 K의 융합 유무 비교**, A↔C는 미융합 FoV 비교다. B↔D는 전체 파이프라인 비교로 표시한다. C2는 필요하면 사전 등록한 별도 보조 비교로 추가하며 validation으로 C2/C3 중 유리한 것을 골라 C라고 부르지 않는다. C3가 식별 불가능하거나 실행되지 않았으면 해당 장면의 A/B만 실행 가능하며 C/D는 미평가로 표시한다. C3가 초기값을 선택했다면 C=A, D=B임을 명시한다.

E0c 재현 제어에서는 **깊이 gate를 끄고** 같은 raw·K·프레임 순서로 기존 색 조건 동작을 재현한다. 이 제어와 깊이 gate가 켜진 주 비교군을 구분해 저장한다. 색 gate만의 이전 결과를 “깊이 근접 조건까지 검증됨”으로 해석하지 않는다.

#### 검증·평가와 SLAM 준비 산출물

- 합성 제어에서 색 차이 30/31, 깊이 범위 3% 경계 안/밖, 같은 색의 먼 표면 거절, 같은 깊이의 다른 색 거절, 그룹 누적으로 범위가 커지는 경우의 거절을 검사한다. float64의 깊이 경계 비교 허용오차는 `1e-8`로 고정하고 별도 기록한다.
- 각 단계의 수용/색 거절/깊이 거절/비투영 수, 평균 Z·새 광선의 대표점, 거절점 좌표 불변, 전체 관측의 중복·유실 없는 CSR를 검증한다. 단계 당시의 카메라·구성원 ID·깊이 범위를 저장해 gate를 독립 재계산한다. 마지막 카메라에서만 검사해 이전 단계까지 검증됐다고 하지 않는다.
- 대표점 수 `N_before/N_after`, 감소율 `1-N_after/N_before`, 그룹 크기 분포·다중 프레임 그룹 비율, 카메라별 고정 영역 coverage·빈 픽셀, 경계/벽 ROI·Z 분포·RGB 투영을 보고한다. 같은 그룹의 대응점이 하나로 치환돼 거리가 0이 된 사실은 독립적인 정합성 향상의 증거가 아니다.
- 융합 전/후 비교는 같은 해당 arm의 K와 렌더 규칙을 사용한다. 원본 raw가 보이던 고정 픽셀을 분모로 coverage를 계산하고, 공통 유효 픽셀에서 front-Z 상대 변화의 median/p90을 보고한다. 사라진 픽셀을 공통 영역 계산에서 빼면서 coverage 손실을 숨기지 않는다. 추가로 전체 arm을 C1 고정 K에서 투영한 비교도 저장한다.
- **점 수 축소·표면 보존의 계획 기준:** 검증 통과, 대표점 수 ≥10% 감소, 모든 카메라의 coverage 감소 ≤0.5 percentage point, 공통 유효 영역의 front-Z 상대 변화 p90 ≤3%. 각 융합 arm의 미융합 입력 대비 판정한다. 이는 raw 표면을 얼마나 보존하는지 보는 압축 기준이며 GT 정확도 기준이 아니다. 조건 미달 시 실제 수치와 실패 이유를 그대로 보고하고 gate를 느슨하게 바꿔 통과시키지 않는다.
- raw/융합 NPZ·PLY, owner 출처 색·출처 membership, 원본 RGB, 단계별 치환·원본→대표점 매핑, `observation_count`와 실행 시간·peak memory·파일 크기를 저장한다. 대표점 배열의 크기와 **원본 관측·CSR를 포함한 총 보관 크기**를 구분한다. provenance를 모두 남기면 총 메모리가 감소하지 않을 수도 있다.
- SLAM 준비 자료로 고유 대표점 ID, 새 대표점 ID와 폐기 ID의 연결, 관측 수, 원본 RGB min/max, 관측 출처·카메라 버전을 보존한다. 향후 FoV/pose가 바뀌면 기존 그룹이 여전히 유효하다고 가정하지 않고 원본 관측에서 재역투영·재융합할 수 있게 한다. raw 자료를 보관소에 남기는 것과 실제 SLAM에서 메모리를 해제하는 정책은 별개다.

점 수 감소·오프라인 처리 시간만으로 SLAM 추적 정확도·실시간성·장기 메모리 안정성이 입증되었다고 하지 않는다. 실제 연속 SLAM 적용과 map 갱신/제거 정책은 후속 실험에서 검증한다.

## 10. 시각화와 저장물

프레임 0/1/2는 각각 **빨강/초록/파랑**으로 표시한다. 이 출처 색과 실제 RGB는 별도 파일로 저장한다. 보정 중 실제 RGB를 바꾸거나 프레임 색을 혼합하지 않는다. C5에서는 owner 출처 색과 여러 프레임에 속하는 membership를 별도로 저장해, 한 대표점을 한 프레임에서만 관측한 것으로 오해하지 않게 한다.

각 카메라에 대해 초기/최종의 다음을 동일 조건으로 저장한다.

1. 전체 점군, 타 프레임 점군만, 출처별 단독 점군의 2D 투영과 frontmost 출처 ID·Z·빈 픽셀 마스크.
2. 동일한 고정 점 렌더러·z-buffer로 만든 원본 RGB 비교와 출처 색 비교. 물체 경계의 점 크기·가림 규칙을 전후 동일하게 적용한다.
3. 원본 Depth와 카메라, 초기/최종 FoV(degree/radian)·fx/fy·β, 후보별 목적함수·coverage·solver 이력.
4. 프레임별·전체 초기/최종 PLY. 월드 좌표계와 점 ID·출처를 보존하고 비교 과정에서 ICP를 적용하지 않는다.
5. C5의 A/B/C/D 동일 해상도 패널, 융합 수용/거절 마스크, 대표점 수·coverage 비교표. 융합 전 원본 점군도 함께 보존한다.

주 비교는 실내 512×384, 드론 512×432의 처리 영상 해상도로 한다. 축소·확대 패널을 만들 경우 원본 RGB도 **같은 크기로 축소한 후 같은 보간법으로 확대**하고 실제 크기를 표기한다. 전후 결과만 흐리게 보이는 불공정한 비교를 피한다. 비교용 렌더링은 손실 최적화에 사용하지 않는다.

## 11. 폴더와 재현성 규칙

실험 코드는 새 `camera_fov_alignment` 계열로 격리한다. 아래는 **향후 실행 시의 구조**이며 이번 계획 작성에서 실행 폴더나 결과를 만들어 완료 상태로 표시하지 않는다.

원본 실행 ID·manifest·체크포인트·파일 해시, 전처리, `R/t/C/K`, 입력 순서, solver/NumPy/OpenCV 버전, seed, 대응·split·ROI·threshold를 기록한다. 후보별 데이터와 prior 손실을 분리하고 실패·초기 선택·미수렴도 보존한다. 기존 결과를 덮어쓰지 않는다.

C0의 수식·소규모 solver 검증은 CPU로 가능하다. GPU가 필요한 계산은 사용자 지침대로 **샌드박스 밖 호스트에서 실행**하고 실행 환경을 기록한다. 계획 작성 단계에서는 추가 패키지를 설치하지 않는다. 단계별 실험 완료 후 코드·설정·중간/최종 결과·한국어 보고서를 커밋·푸시하고, 로컬 commit과 원격 반영을 각각 확인한다. 대형 산출물의 추적 방식은 기존 저장소 규칙을 따른다.

## 12. 관련 연구와 주장 범위

[DUSt3R §3.4 Global Alignment](https://arxiv.org/html/2312.14132v3#S3.SS4)는 카메라·깊이 등의 매개변수화와 전역 정렬을 참고할 선행연구다. 이번 계획은 그 전체 방법의 재현이 아니라 **VGGT-Ω의 원본 Depth·카메라 중심·회전을 고정한 FoV 한정 보정**이다. 이 제한된 설계의 성공·실패를 더 큰 자유도를 가진 카메라/깊이 공동 최적화 전체로 확대 해석하지 않는다.

첫 실행 작업은 **C0: 역투영 불변성·affine 수식·합성 복구·퇴화 검증**이다. 현재 문서는 실험을 수행하거나 효과를 확인했다는 보고서가 아니다.
