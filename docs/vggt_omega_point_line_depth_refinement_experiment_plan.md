# C3a를 기준으로 한 점·선·깊이 제약 기반 Pointmap 보정 실험 계획

> 작성일: 2026-11-13 · 상태: **G0~G6 및 G0a/G0b/G5a 실행 완료 · 효과 판정은 탐색적**<br>
> 연구 용도: 대학원 졸업논문 실험<br>
> 실험 계열: `point_line_depth_refinement`, 코드 `G0`~`G6`<br>
> 주 입력: 기존 TUM `freiburg1_desk` 실내 RGB 3장(index 30/40/50)의 VGGT-Ω 공동 추론 결과<br>
> 질문: **C3a의 FoV 보정에 선 대응과 깊이 제약을 추가하면 프레임별 표면의 정합과 형태가 어떻게 달라지는가?**

실행 결과는 [종합 보고서](experiments/point_line_depth_refinement/summary.md)와 [구현·검증 기록](experiments/point_line_depth_refinement/amendments.md)을 따른다. 아래 내용은 사전 계획이며 실제 지원 부족·기술 검증·수치 변화는 실행 보고서와 구분한다.

관련 후속 조사: [PlanarGS에서 재사용할 수 있는 요소](research/planargs_reuse_review.md). 이 링크는 문헌 조사이며 새 평면 보정 실험의 실행 완료를 뜻하지 않는다.

## 1. 배경과 범위

사용자는 C3a의 `proposed_not_selected` PLY에서 기존 실험보다 높은 표면 정합도를 육안으로 확인했다. 이 관찰을 후속 실험의 출발점으로 삼는다. 기존 C 계열의 자동 판정은 해당 후보의 표면이 실제로 나쁘다는 증거가 아니다. 반대로 육안 관찰만으로 실제 깊이 정확도가 검증된 것도 아니다.

기존 [FoV 계획](vggt_omega_fov_pointmap_alignment_experiment_plan.md)의 종료 상태와 결과를 보존한다. 이번 사용자 요청에 따른 새 연구를 G 계열로 분리하며 C3a를 덮어쓰거나 기존 기준을 소급 변경하지 않는다. 개별 정점을 RGB 손실로 이동했던 E 계열도 재개하지 않는다.

[VGGT-Geo 논문 §3.1–3.3](https://www.mdpi.com/2220-9964/15/2/85)은 사전학습 모델로 초기 기하와 관측 정보를 얻고, 점·선 대응 및 깊이 사전정보로 카메라와 깊이를 공동 보정한다. 선 위의 픽셀을 역투영한 뒤 다른 영상의 대응 선까지 재투영 거리를 줄이는 방식이 참고 대상이다. **이번 계획은 그 아이디어를 C3a에 추가하는 자체 구현이며 VGGT-Geo의 공식 실행·전체 재현이 아니다.** 저자 코드는 확보하지 못했다. DINOv3 신뢰도 모듈, LETR, MASt3R, SLAM backend 전체를 동일하게 구현했다고 표시하지 않는다.

먼저 C3a와 같은 FoV 자유도에서 제약별 효과를 분리한다. 다음 단계에서만 제한된 깊이 보정을 허용한다. 주 실험 전체에서 카메라 중심·회전·주점·RGB는 고정한다. 카메라 자세 공동 최적화, 자유 정점 이동, RGB 렌더 손실, 평면 강제 투영은 범위 밖이다.

## 3. 변수와 제약의 정의

### 3.1 FoV와 역투영

기존과 같이 `βx=fx0/fx`, `βy=fy0/fy`의 6개 변수를 둔다. 범위는 원본 초점거리 기준 `fx,fy ∈ [0.90,1.10]×초기값`, 즉 `β ∈ [1/1.10,1/0.90]`로 유지한다. C3a에서 다시 ±10%를 허용해 범위를 누적 확대하지 않는다.

```text
Q_i(u) = D'_i(u) * [(u_x-cx)/fx_i, (u_y-cy)/fy_i, 1]
P_i(u) = C_i + inverse(R_i) * Q_i(u)
projection_j(P) = pi(K_j * (R_j*P + t_j))
```

Z-depth와 광선 거리를 혼동하지 않는다. 모든 후보에서 같은 픽셀·RGB로 재역투영하고 융합·점 삭제는 하지 않는다.

### 3.2 P: 기존 점 대응 제약

`L_P`는 기존 C3a의 고정 fit 대응, 양방향 카메라 좌표의 깊이 정규화 3D 차이, Z축 제곱 가중 4배, Huber δ=0.01, 카메라 쌍·방향 동일 가중 평균을 그대로 유지한다. β prior는 `0.001*mean((β-1)^2)`다. 코드·설정과 실제 수식의 일치를 G0에서 검사한다.

새 대응 추출기로 바꾸는 효과와 제약 추가 효과를 섞지 않는다. 영상 점 재투영 오차는 평가에 추가하지만 주 P 손실을 동시에 교체하지 않는다. matcher 교체가 필요하면 `G1a` 등 별도 보조 실험으로 분리한다.

### 3.3 L: 선분 대응 제약

서로 다른 영상에서 같은 물리적 경계로 판단한 선분 쌍을 고정한다. 기준 영상의 선분 위 샘플을 Depth로 역투영하고, 타 영상의 대응 직선까지의 수직 거리를 줄인다. 양방향을 계산한다.

```text
r_L(i→j,u) = (a_j*x' + b_j*y' + c_j) / 2 pixel
(x',y') = projection_j(P_i(u)),     a_j²+b_j²=1
```

무차원 잔차에 Huber δ=1을 사용한다. 샘플은 선분 양 끝 10%를 제외한 구간에서 8 pixel 간격, 최소 3개다. 길이가 긴 한 선이 지배하지 않게 샘플 평균 → 선 대응 평균 → 쌍·방향 평균 순서로 집계한다. 깊이 불연속 지지 픽셀은 고정 마스크로 제외한다.

선의 양 끝점은 영상별 가림·검출 길이가 다르므로 같은 3D 지점이라고 강제하지 않는다. 다만 무한 직선으로의 잘못된 대응을 줄이기 위해 결과의 선분 범위 이탈 비율도 별도 보고한다. 선 방향만 비슷하다는 이유로 대응시키거나 모든 벽을 직교·평면으로 강제하지 않는다.

### 3.4 Z: 교차 시점 깊이 제약

G1에서 고정한 영상 대응 `(i,u)↔(j,v)`에서 다음을 계산한다.

```text
z_ij = [R_j*P_i(u)+t_j]_z
r_Z(i→j) = (z_ij - D'_j(v)) / (0.01 * D0_j(v))
```

양방향 Huber δ=1을 쌍별 동일 가중 평균한다. 분모는 원본 Depth에서 고정한다. 후보마다 최근접점이나 z-buffer의 앞 점을 바꿔 손실을 낮추지 않는다. 깊이 대응은 P에 사용한 fit 대응에서 읽으며, 별도의 독립 관측이 추가된 것으로 해석하지 않는다. **P에도 Z 성분이 있어 P+Z는 주로 깊이 방향 가중을 강화하는 ablation**이다.

### 3.5 A: 깊이 보존 prior와 실제 깊이 변수

Depth를 고정하는 G2에서는 `D'=D0`이므로 원본 Depth 보존 prior는 항상 0이다. 이를 추가 제약의 효과라고 보고하지 않는다.

G3에서만 `D'_i(u)=exp(s_i)*D0_i(u)`를 허용한다. 공통 scale의 자유도를 줄이기 위해 `s_0=0`을 고정하고 나머지 두 카메라의 배율을 `[0.95,1.05]`로 제한한다. 변수는 β 6개와 깊이 배율 2개, 총 8개다. 이는 픽셀별 깊이 최적화가 아닌 제한된 프레임별 깊이 배율 보정이다.

`L_A=mean((s_i/log(1.05))²)`를 자유 깊이 변수에 적용한다. 깊이 변화의 직접 한계와 soft prior를 함께 기록한다. 기준 카메라의 깊이 오차를 남긴 채 상대 깊이를 맞추는 한계가 있으며 실제 scale을 회복했다고 주장하지 않는다.

### 3.6 E: 외부 깊이 prior (G4 조건부)

G3가 기술 검증을 통과하면 동일 RGB에 대한 MoGe-2 깊이를 별도 고정 prior로 도입한다. checkpoint·입력 전처리·출력 depth 정의를 검증한 뒤 실행한다. 모델 접근·호환성이 확보되지 않으면 `BLOCKED_EXTERNAL_PRIOR`로 남기고 다른 모델로 조용히 대체하지 않는다.

Omega 좌표계와 외부 깊이를 맞추는 **공통 scale 1개**는 G1에서 정한 fit 영상 타일의 고정 유효 픽셀로 G4 최적화 전에 산출·동결한다. 카메라별 scale을 따로 맞추거나 후보마다 재적합하지 않는다. validation 타일·GT는 이 보정에 사용하지 않는다. `L_E`는 `(D'-D_external_aligned)/(0.05*D0)`의 Huber 평균이며 프레임별 동일 가중이다. 외부 예측은 GT가 아니고, 이 scale 정렬 후 metric 정확도가 검증되었다고 하지 않는다.

## 4. 관측 생성과 검증 분리

G1은 최적화 전 원본 영상만으로 관측·split·ROI를 확정한다.

- **점:** C3a의 기존 track 및 fit/validation split을 재사용한다. 부족한 지원 수를 숨기거나 기준을 소급 완화하지 않는다.
- **선:** 처리 RGB에서 OpenCV LSD를 후보 검출기로 사용한다. 최소 길이 40 pixel, 프레임당 최대 100개로 제한한다. 대응은 영상의 실제 물체·모서리를 확인해 annotation JSON과 대응 overlay로 남긴다. 검토자·수정 이력을 기록한다. 자동 대응만 사용하는 경우 별도 코드로 분리하고 동일 품질이라고 간주하지 않는다. 구현은 [OpenCV LineSegmentDetector 문서](https://docs.opencv.org/4.x/db/d73/classcv_1_1LineSegmentDetector.html)를 참조한다.
- 대응 annotation은 재구성 결과·손실 감소를 보기 전에 완료한다. 같은 모서리의 분절선·여러 프레임 관측은 하나의 구조 ID로 묶고 전부 같은 split에 넣는다. 동일 벽 모서리를 fit과 validation에 나눠 독립 선 검증처럼 세지 않는다.
- 구조 ID의 고정 hash와 seed 0으로 약 80/20 fit/validation을 나눈다. 각 쌍에서 fit 선 track 5개, validation 2개, 두 개 이상의 방향군(방향 차이 20° 이상)을 사전 지원 기준으로 둔다. 미달하면 선 관련 결과를 `LOW_SUPPORT_DIAGNOSTIC_ONLY`로 보존한다. 샘플 수 100개가 한 선에서 나왔다고 100개 독립 대응으로 세지 않는다.
- 점·선 fit/validation의 실제 공유 픽셀과 구조 중복을 감사한다. 공유 관측이 발견되면 line-fit에서 해당 지지 관측을 제거하고 목록을 동결한다. 같은 장면·벽을 보는 관측 간 상관은 남으므로 완전히 독립적인 일반화 평가라고 부르지 않는다.
- Depth 보간은 기존처럼 bilinear, finite·positive 및 지지 픽셀 상대 깊이 범위 3% 이내 조건을 사용한다. 후보값에 따라 지지 마스크를 바꾸지 않는다. 원본 confidence 마스크도 고정한다.
- 벽·책상·물체 경계 ROI를 보정 전에 저장한다. 평면 두께 평가는 실제 평면으로 볼 수 있는 ROI에만 적용하며, 곡면·책상 위 물체를 벽으로 강제하지 않는다.

기존 실내 데이터는 이미 결과를 관찰한 탐색 데이터다. split을 고정해도 새로운 미관측 데이터 검증으로 격상시키지 않는다. G5의 추가 실내 구간은 원본 index 100/110/120을 사전 후보로 삼고, 존재·입력 overlap만 확인한다. 미존재·낮은 overlap이면 그 사실을 기록하고 성능을 본 뒤 좋은 구간으로 교체하지 않는다.

| F-P | β 6개 | P + β prior | C3a 재현 제어 |
| F-PL | 동일 | P + L + β prior | F-P 대비 선 제약 |
| F-PZ | 동일 | P + Z + β prior | F-P 대비 깊이 방향 강조 |
| F-PLZ | 동일 | P + L + Z + β prior | 두 제약 결합·상호작용 |

G3는 위 네 군에 동일한 깊이 배율 자유도와 A prior를 추가해 이름을 D-P/D-PL/D-PZ/D-PLZ로 한다. D-PLZ만 단독 실행해 F-P와 비교하면 변수 증가와 제약 증가를 구분할 수 없으므로 네 군을 함께 수행한다.

모든 주 군은 B1의 β에서 시작한다. F-P가 원래 C3a 해를 재현하는지 먼저 검사한다. G5에서만 β=1 초기값으로 같은 군을 반복해 비선형 초기값 의존성을 확인한다. B1의 깊이는 원본이므로 G3의 초기 깊이 배율은 모두 1이다.

G6 이후 색·깊이 gate 융합이 필요하면 `G6a`로 별도 계획·실행한다. 주 비교의 점 수와 색을 보존해 표면 정합 변화와 융합·삭제 효과를 섞지 않는다. G6a는 현재 실행 범위에 포함하지 않는다.

## 6. 손실 가중치와 최적화

P는 기존 C3a 구현을 보존한다. 다른 단위의 항을 무작정 더하지 않도록 G1 종료 시 B1의 fit 손실만으로 `S_P=max(L_P(B1),1e-8)`, `S_L=max(L_L(B1),1e-8)`, `S_Z=max(L_Z(B1),1e-8)`를 산출·동결한다. P군에도 같은 `S_P`를 사용한다.

```text
L = (L_P + 0.001*mean((β-1)^2))/S_P
    + 0.25*L_L/S_L           # L군에서만
    + 0.25*L_Z/S_Z           # Z군에서만
    + 1.0*L_A               # D군에서만
    + 0.25*L_E/S_E          # G4의 E군에서만, S_E도 B1 fit에서 동결
```

P와 β prior를 함께 같은 상수로 나누므로 P-only의 최적해는 바뀌지 않아야 한다. 초기 손실이 `1e-8` 이하인 항은 `NO_INITIAL_RESIDUAL`로 표시하고 해당 항 추가 결과를 주 개선 근거로 삼지 않는다. 정규화에 사용한 값·유효 수·각 항 loss·gradient norm을 모두 보고한다.

이 가중치는 본 실험의 사전 선택이며 보편적인 최적값이 아니다. G5에서 추가항의 가중치를 각각 0.1/0.25/1.0으로 한 번에 한 항씩 바꿔 민감도를 보고한다. validation·GT·육안으로 가장 좋은 가중치를 골라 주 결과를 교체하지 않는다.

선 재투영·깊이 배율을 추가하면 원래 C3a의 affine 문제와 달리 일반적으로 비선형이다. 작은 bounded nonlinear least-squares solver를 float64로 사용하고 구현·버전을 기록한다. analytic/autodiff Jacobian을 중앙 차분과 비교한다. 최대 200 iteration, 함수 평가 한도 2,000, `ftol/xtol/gtol=1e-8`을 기본으로 삼고 실제 종료 사유를 남긴다. 수렴 플래그만으로 성공 판정하지 않는다.

투영 Z가 비양수이거나 계산이 비유한 후보는 유효한 개선 후보로 수용하지 않는다. solver 내부에는 유한 penalty를 정의하고 G0에서 검증한다. 범위를 벗어난 투영도 고정 관측을 손실에서 빼지 않는다. 정해진 관측 수를 유지하며 invalid 수·최악 잔차를 함께 기록한다.

G0에는 알려진 FoV·깊이 배율을 가진 합성 점·선 제어, 잘못된 선 대응, 단일 방향 선, 순수 회전·공통 중심·평면 장면, 깊이 gauge 제어를 포함한다. prior를 제외한 데이터 Jacobian rank·특이값·조건수를 측정한다. prior로만 정해진 변수를 기하적으로 식별되었다고 부르지 않는다.

## 7. 후보 보존과 평가

### 7.1 제안값과 자동 선택값을 분리

각 군에서 다음을 모두 저장한다.

- `initial`: B1 초기값.
- `proposed`: fit 총손실 기준 최선의 유효 후보. validation·GT·육안은 선택에 사용하지 않는다.
- `selected`: 기존의 coverage 기준을 만족하는 저장 후보 중 fit 손실 최선값. 후보가 없으면 initial을 반환하고 그 상태를 명시한다. B1 자체가 raw 대비 기존 coverage 기준을 위반하므로 initial 반환은 기준 통과를 뜻하지 않는다.
- `last`: solver의 마지막 유효 후보와 종료 사유.

coverage는 B0와 B1 각각을 분모로 두어 모두 보고한다. 기존처럼 초기 유효했던 **점 관측**의 frustum 유지율과, 실제 렌더링의 **픽셀** coverage를 구별한다. 자동 선택에는 B0 기준 각 카메라 방향의 frustum 손실 ≤0.5 percentage point와 비유한 값 없음 조건을 사용한다. B1 기준 값은 추가 변화의 진단이다. 탈락한 proposed도 PLY·지표에서 제외하지 않는다.

### 7.2 수치 평가

fit와 고정 validation에서 쌍별·전체 median/mean/p90 및 유효 수를 제시한다.

1. 고정 점 대응의 양방향 정규화 3D 거리·카메라 Z 차이·픽셀 재투영 오차.
2. 보류 선 track의 재투영 거리(pixel), 선분 범위 이탈, 방향별·구조별 결과.
3. 고정 벽 ROI의 출처별 깊이 분포·층 사이 거리와 단면. B1에서 한 번 적합한 기준 평면을 고정해 출처별 signed distance를 비교한다. 후보마다 평면을 다시 맞춰 얇아 보이게 하지 않는다. 실제 평면성은 별도 참고로만 보고한다.
4. β/FoV·깊이 배율 변화, bound 도달, data Jacobian rank와 수렴, frustum 유지율·픽셀 coverage·빈 픽셀·invalid 수.
5. 외부 prior를 사용했다면 prior와의 일치도는 목적함수 만족으로 표시한다. 독립적인 정확도 증거로 세지 않는다.

사전 비교 기준은 **B1 대비 validation 3D median ≥5% 감소**, 절대 감소 ≥`1e-5`, 쌍별 악화 ≤1%, B1 기준 frustum 손실 ≤0.5 percentage point다. 깊이층 개선을 말하려면 validation Z median과 고정 벽 층 간 거리도 각각 ≥5% 감소해야 한다. 벽의 출처별 표본 수·전체 두께를 함께 보고, 점 삭제나 크기 축소에 의한 가짜 개선을 검사한다. 작은 분모는 `max(기준값,1e-5)`로 계산한다.

이 수치는 이번 연구의 사전 기준이며 GT 정확도 기준이 아니다. 지원 부족·rank 부족이면 수치 변화와 육안 관찰을 그대로 보고하되 종합 판정은 탐색적/보류로 둔다. 항목별로 개선·악화·상충을 표시하며 하나의 RGB 오차나 coverage만으로 전체 3D 품질을 좋다/나쁘다로 결론내리지 않는다.

### 7.3 육안·GT 평가

동일 renderer·점 크기·가림 규칙으로 B0/B1/각 군의 proposed/selected를 나란히 제시한다. 원본 픽셀 RGB PLY와 프레임 출처색 PLY를 각각 저장하고 프레임 0/1/2 색은 빨강/초록/파랑으로 고정한다. 원본 픽셀색을 평균하거나 학습하지 않는다.

각 카메라에서 전체 점·타 프레임 점만·출처별 점을 투영하고, 고정한 외부 관찰 시점과 벽 단면도 저장한다. 기하 비교는 B0 고정 K의 공통 카메라 투영과 각 후보 K 투영을 구분한다. 원본 RGB도 동일 해상도·보간법으로 줄이고 확대한다. 데이터 변경 없는 동일 조건의 PLY 육안 확인을 수치와 나란히 기록한다.

TUM GT를 쓰는 경우 기존 자료의 K·pose·depth 시각 동기와 resize/crop을 먼저 재검증한다. 모델↔GT scale·정렬은 B0에서 한 번 정해 전 후보에 고정하며 GT로 변수·가중치를 선택하지 않는다. G2는 자기 Depth가 고정되어 있으므로 자기 Depth GT 오차의 불변을 확인한다. G3/G4에서는 그 오차가 실제로 달라질 수 있다. GT 검증이 완료되지 않으면 내부 정합성·육안 결과까지만 보고한다. 추가 실내 구간과 일반 VGGT도 각각 별도 좌표계의 결과임을 명시한다.

```text
experiments/point_line_depth_refinement/G0/ ... G6/
results/point_line_depth_refinement/{dataset}-{code}-{YYYYMMDD}-{seq}/
  stages/{code}/

docs/experiments/point_line_depth_refinement/index.md

```

각 arm의 `initial/proposed/selected/last` 아래에 `pointmap.npz`, `pixel_rgb.ply`, `frame_colors.ply`, 카메라 설정과 배열 해시를 저장한다. 실행 보고서는 한국어로 작성한다.

입력 RGB·NPZ·대응·annotation·split·ROI·코드 revision·checkpoint·의존 버전·실행 명령·seed·실행 시간/메모리·실패 로그를 기록한다. 파생 비교군 사이에 입력 해시와 관측 ID가 일치하는지 확인한다. 기존 C/E/V 실행 산출물은 변경하지 않는다.

첫 실행은 **G0**다. 재현 오차와 합성 검증이 통과하면 G1을 동결하고 G2를 수행한다. 선 지원이 부족하면 그 상태를 명시한 탐색 실행으로만 진행하며 효과 확정을 주장하지 않는다. G3/G4는 선행 기술 검증 통과 후 실행한다. 보조 검증은 G0a/G1a 등으로 분리하고 실패·중간 결과를 보존한다.

계획 작성만으로 실험 실행이나 개선을 완료했다고 표시하지 않는다. 모델 설치·다운로드·GPU 실행은 후속 실행 단계에서 수행하며 GPU는 사용자 지침대로 **샌드박스 밖 호스트**에서 실행한다. 각 실험 완료 후 코드·설정·한국어 보고서·경량 중간/최종 결과를 GitHub에 커밋·푸시하고 원격 반영을 확인한다. 대형 PLY/NPZ는 기존 `.gitignore` 규칙에 따라 로컬 results에 보존하고 경로·크기·해시를 추적 문서에 남긴다.
